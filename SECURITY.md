# Security Policy

## Reporting a vulnerability

If you discover a security vulnerability in BetterSanFernando, please do
**not** disclose it publicly (for example, in a public issue or PR).

Preferred: use GitHub's [private vulnerability reporting][ghsa] on this
repository, if it is enabled.

If private vulnerability reporting is unavailable, contact a project
maintainer directly rather than opening a public issue, and avoid including
exploit details in any public channel.

We do not currently operate a bug bounty program or commit to a fixed
response-time SLA. Reports are reviewed on a best-effort basis.

## What is not a security vulnerability

- Ordinary bugs (broken UI, incorrect rendering, etc.) belong in the **Bug
  report** issue form.
- Incorrect or outdated civic data (services, projects, records, etc.)
  belongs in the **Civic data correction** issue form. Civic-data accuracy
  issues are not security vulnerabilities.

[ghsa]: https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability
